Build AI workflows around written handoffs

If you keep copying one AI output into the next prompt, turn those handoffs into a repeatable workflow.

November 23, 2026

  1. Map the files first

    Before chaining skills, write down what each step reads and produces. For an offer launch, research writes market.md, sales copy reads market.md and writes landing.md, and email drafting reads both. This makes dependencies explicit and gives you intermediate work to inspect.

  2. Give one skill the sequence

    Create an orchestrator skill that lists the component skills in order, their input files, and their required outputs. Keep research, copywriting, and email drafting usable independently so you can reuse them in other workflows.

  3. Separate execution from delivery

    In Claude Code, use `context: fork` in the orchestrator's frontmatter to run it in a separate context. Specify that it should return the final brief and links to supporting files. Forking the orchestrator does not automatically give every component skill its own separate context.

  4. Put review before errors spread

    Add a checkpoint after research to approve the audience, offer, and supporting evidence before drafting downstream assets. Require later steps to flag missing inputs instead of inventing them. Written handoffs make errors easier to find, but they can also carry a bad assumption through the entire workflow.

Why it matters

A solo builder can spend less time moving text between prompts and more time reviewing decisions. Saved intermediate files let you trace a weak final draft back to its inputs and rerun the affected steps. Start with one recurring process that already has clear stages.
