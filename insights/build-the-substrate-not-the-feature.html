Build the Substrate, Not the Feature

Most of the software you are building today will be made obsolete by the next model update unless you focus on the right layer of the stack.

November 19, 2026

  1. Design for the Bitter Lesson

    Stop writing complex conditional logic for tasks that require reasoning. If a frontier model can likely solve it better in six months, your custom code is future technical debt. Focus your engineering on timeless infrastructure like data governance, security schemas, and high-speed APIs that provide clean context to any model.

  2. Let AI Architect the Workflow

    Instead of automating an existing manual process, use a frontier model to design a new one from the ground up. Small businesses often try to map AI onto messy human habits. A better approach is asking a reasoning model to build the architecture of the workflow itself, using your existing data tools as the primary building blocks.

  3. Optimize for the 10-to-1 Agent Ratio

    Prepare for a world where your systems have ten agent users for every one human user. This means prioritizing high-throughput, structured data interfaces over traditional UIs. If an autonomous agent cannot quickly query and extract data from your system without navigating a human-centric front end, your software becomes a bottleneck.

  4. Implement a Hybrid Model Stack

    Use a tiered strategy to manage costs without sacrificing quality. Assign high-volume, repetitive tasks like data extraction or simple classification to open-weights models. Reserve expensive frontier models for high-level orchestration, planning, and error recovery to keep your token spend sustainable as you scale.

Why it matters

For a small builder, resources are too scarce to waste on features that will be free in the next GPT or Claude update. By focusing on the context and governance layer, you build a defensible system of record that remains valuable no matter which model is winning the intelligence race.
