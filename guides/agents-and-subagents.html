Agents & Sub-Agents

Level 2, intermediate. Your first weeks with Claude Code or Codex: how an agent uses tools and files, when to split work across sub-agents, and how to keep it on the rails.

Updated June 25, 2026

This guide is for people who already chat with AI comfortably and are trying a coding agent like Claude Code or Codex for the first time. You will learn how agents use tools, project context, sub-agents, skills, loops, and MCP connectors so you can let an agent inspect files, run commands, make small edits, and verify its work without losing control.

Who this is for: You are trying Claude Code or Codex for the first time and want your agent to use tools, edit files, and delegate to sub-agents well.

In this guide

What Makes a Coding Agent Different From a Chatbot

A coding agent is different because it can turn a request into a loop of reasoning, tool use, observation, and follow-up action inside your real project.

Give the Agent the Right Project Context

A coding agent edits better when your repository contains a small, reliable map of what matters, where to look, and what rules must not be broken.

Turn Repeated Work Into Reusable Skills

A skill turns a task you keep explaining to an agent into a small reusable workflow with instructions, scripts, assets, checks, and known failure cases.

Use Sub-Agents Without Creating Chaos

Sub-agents are useful when they reduce shared assumptions, file conflicts, or waiting time, but they only help if you give each agent a clear lane and verify the results before combining them.

Connect Agents to Real Tools With MCP and Connectors

MCP and connectors turn a coding agent from a chat box into a tool-using worker, but the real skill is deciding which tools it may touch, what context it receives, and where humans stay in the loop.

Build Your First Safe Agent Loop

A safe agent loop is a small repeatable system: start it on purpose, give it one job, make it prove progress, and stop it before it wastes time or tokens.
