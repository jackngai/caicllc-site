The Artifact Chain: Engineering Intent for Autonomous Workflows

High-velocity autonomous engineering requires a shift from interactive prompting to a machine-actionable lifecycle where structured artifacts drive agent execution without human steering.

Updated September 6, 2026

The Intent-Centric State Machine

The primary bottleneck in autonomous engineering is the loss of context during long-running tasks. When an agent moves from planning to execution, a single prompt is rarely enough to sustain the technical nuance required for a complex feature. Level 3 builders address this by implementing an artifact chain: a sequential series of markdown documents that serve as the project's source of truth. This chain starts with an intent file, which is not a simple user story but a machine-actionable definition of success. It captures the constraints, domain context, and desired outcomes through a process of agent-led discovery.

Before a single line of code is written, a scout agent interviews the human developer to extract latent knowledge. This prevents the agent from making assumptions about the existing architecture or business logic. Once the intent is crystallized, it generates a technical specification and a step-by-step plan. These artifacts exist in the repository, allowing independent agent threads to pick up work with a full understanding of the state. This structure transforms the workflow from a series of tactical chats into a predictable state machine where each document provides the deterministic guardrails for the next phase of the build.

Adversarial Planning and the Harness

Once the artifacts are defined, the engineering focus shifts to the harness: the environment and architectural constraints surrounding the model. A clean, modular codebase acts as a force multiplier, enabling smaller and cheaper models to execute tasks that would otherwise require top-tier reasoning capabilities. The harness is further optimized through adversarial prompting. Instead of asking an agent to create a plan, use a process where the model is tasked to challenge the requirements. This technique forces the LLM to identify edge cases, architectural mismatches, and missing dependencies before the execution phase begins.

This strategic programming model treats syntax as a commodity and architecture as the primary lever. By maintaining strict scoping and interface boundaries, you allow agents to operate within highly isolated sandboxes. In these environments, you can run multiple agents in parallel to solve the same problem. The harness then uses deterministic code to evaluate which agent produced the most efficient, passing solution. This move from human-in-the-loop to human-on-the-loop requires a shift in mindset: your job is no longer to write code, but to design the system that manages the agents writing the code.

Separating Execution from Deterministic Validation

A common failure in autonomous loops is the reliance on the agent to verify its own work within the same context window. This leads to hallucinations where the agent claims a test passed when it actually failed. To achieve high-reliability AFK workflows, you must decouple the non-deterministic agent from the deterministic validation layer. This is achieved by running the build agent inside a specialized sandbox and then invoking external tools like linters, type-checkers, and unit tests through an SDK. The agent is only notified of the results; it does not control the execution of the validation itself.

This separation allows for a software factory model where tasks are routed based on their nature. A router analyzes the intent and directs it to a specific workflow for chores, bugs, or features. For instance, a bug fix might trigger a diagnostic agent that monitors system logs to generate its own intent file before a human even realizes there is an issue. This proactive maintenance loop ensures that the agentic layer is constantly refining the codebase, with human intervention reserved for final architectural reviews or high-level strategic decisions.

Stateful Skills and Autonomous Maintenance

The final stage of the artifact chain is the persistence of learned context across sessions. Advanced builders use stateful skills: local records of previous failures, successful patterns, and mission-specific objectives. When an agent finishes a task, it writes a post-mortem to its local memory. This ensures that if a similar problem arises in a future autonomous loop, the agent does not repeat past mistakes. This local context is more valuable than the model's base training because it is grounded in your specific repository and engineering standards.

By the time an agent submits a pull request, it should provide comprehensive proof of success. This includes video recordings of UI tests or screenshots of browser interactions generated by tools like Playwright. This evidence-based handoff reduces the cognitive load on the human reviewer. The loop finally closes when the agent transitions into a monitoring state, where it watches for regressions or performance degradation. By engineering the entire lifecycle around artifacts rather than prompts, you create a self-sustaining system capable of complex project transitions with minimal steering.

Key takeaways

  • Replace manual prompts with an artifact chain of intent, spec, and plan files to maintain state across long-running autonomous loops.
  • Implement agent-led discovery and adversarial design reviews to identify architectural flaws before execution starts.
  • Decouple the LLM from validation by using external, deterministic tools for linting and testing rather than letting the agent verify itself.
  • Utilize isolated sandboxes to parallelize execution, allowing multiple agents to compete for the most efficient solution.
  • Move human checkpoints to the end of the pipeline by requiring agents to provide verifiable proof of success through automated logs and video evidence.
  • Adopt a software factory approach by using routers to direct tasks into specific, pre-defined agentic workflows based on context.
