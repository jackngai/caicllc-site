Directing Agents with Intent Documents

Move beyond simple chat prompts by using structured markdown files to guide autonomous agents through complex coding workflows.

Updated October 18, 2026

From Chatting to Directing

When you use a standard AI chat, the interaction is usually a one-off request followed by a response. Coding agents like Claude Code or Cursor function differently because they use tools. A tool is a specific capability granted to the AI, such as the ability to read a file, run a terminal command, or search your directory. Because these agents can take actions in your environment, they require a higher level of precision than a simple chat message. If you give a vague instruction, the agent might start editing files or deleting code based on a misunderstanding.

To prevent this, you must move from prompting to documenting. The most effective way to manage an agent is through an intent document, often named intent.md. This file acts as the single source of truth for the task at hand. Instead of typing a long instruction into a terminal, you create this file in your project folder. The agent reads this file to understand its boundaries, goals, and the specific technical requirements it must meet. This shifts your role from a coder to a manager who defines the 'what' while the agent determines the 'how'.

The Agent Interview and Discovery

Establishing a strong intent document begins with an interview phase. Rather than writing the entire specification yourself, you can ask the agent to interview you. The agent uses its reasoning capabilities to ask about edge cases, existing dependencies, and your preferred architecture. As you answer these questions in the chat, the agent updates the intent.md file. This process ensures that the agent has captured the necessary context before it touches your codebase. Context refers to the background information the AI needs to make correct decisions, such as knowing which libraries you use or how your data is structured.

Once the intent is clear, the agent can expand this into a chain of artifacts. This includes a technical specification and a step-by-step execution plan. By breaking the work into these distinct files, you create a trail of logic that survives even if the agent hits a limit or needs to restart. These documents serve as a map, allowing the agent to track which parts of the plan are finished and which are pending. This structure prevents the common problem of an AI 'forgetting' the original goal halfway through a complex task.

Orchestrating with Manager Loops

Complex tasks often overwhelm a single agent thread. To solve this, you can implement a manager loop architecture. In this setup, one primary agent acts as a supervisor. This supervisor does not do the heavy lifting of writing code. Instead, it reads the intent document and delegates sub-tasks to specialized sub-agents. A sub-agent is a separate instance of the AI focused on a narrow, isolated goal, such as writing a specific test suite or refactoring a single function. This prevents the main agent from getting bogged down in too much detail, which often leads to errors.

To keep these sub-agents on track, the supervisor provides them with recipe cards. A recipe card is a small, focused set of instructions derived from the main intent document. It tells the sub-agent exactly what to do, what files it can access, and when it must stop to ask for human approval. By using these smaller loops of activity, you can manage much larger projects. You remain the high-level decision maker, reviewing the work of the supervisor agent while it manages the technical minutiae of the sub-agents.

Verification and Autonomous Success

The final step in directing an agent is ensuring the work actually meets the requirements laid out in your intent document. High-autonomy agents use verification tools to prove their success. For example, an agent might use a browser tool to take a screenshot of a new UI component or run a test script to confirm a bug is fixed. These proofs should be linked back to the original intent file. If the agent cannot provide proof of success, it should flag the error and wait for your intervention rather than guessing at a fix.

This workflow changes your relationship with the terminal. Instead of writing code, you spend your time reviewing the intent, spec, and plan, then approving the agent's progress at key checkpoints. If an agent encounters an error it cannot resolve, it updates the intent document with the new findings and asks for guidance. This proactive approach ensures that your codebase remains stable while the agent works in the background. By treating your requirements as machine-actionable documents, you turn the agent into a reliable partner that stays on track through even the most rigorous development cycles.

Key takeaways

  • Start every complex task by having the agent interview you to populate an intent.md file.
  • Use an artifact chain consisting of an intent, a spec, and a plan to maintain context across long sessions.
  • Operate as a supervisor by delegating sub-tasks to sub-agents instead of using a single chat thread.
  • Define recipe cards for sub-agents to limit their scope and prevent unintended changes to your codebase.
  • Require agents to provide concrete proof of success, such as test logs or screenshots, before closing a task.
