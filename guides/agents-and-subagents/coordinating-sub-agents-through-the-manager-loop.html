Coordinating Sub-Agents through the Manager Loop

Move beyond basic prompting by using a supervisor agent to design structured workflows and delegate technical tasks to specialized sub-agents.

Updated October 25, 2026

The Manager Loop Framework

When you first use a coding agent like Claude Code, your instinct is likely to treat it as a more capable chat interface. You give it a task, and it writes the code. However, as projects grow in complexity, a single agent's memory can become cluttered, leading to errors or 'hallucinations' where the AI loses track of the file structure. To scale your output, you must shift your role from a prompt engineer to a project manager. This starts with the Manager Loop: a workflow where a primary supervisor agent acts as your interface, interviewing you to understand the high-level goals before any code is written.

In this setup, the supervisor does not immediately execute the work. Instead, it uses its 'tools' (pre-defined functions that allow it to interact with your terminal, file system, or APIs) to map out the requirements. It creates a 'recipe card' for the project. This card acts as a shared state, ensuring that even if different sub-agents are called in to perform specific tasks, the overall objective remains grounded in a single source of truth. By having the agent interview you first, you ensure that the boundaries of the task are well-defined and that you have established clear approval checkpoints.

Structuring Work with Graph Engineering

Once the supervisor agent has a clear recipe, it utilizes graph engineering to organize the execution. Think of a graph as a flowchart where each node is a specific action or a sub-agent. Instead of a 'swarm' of agents talking all at once, graph engineering provides a predictable path. A key pattern here is 'fan-out.' The supervisor identifies independent sub-tasks, such as updating a database schema and refactoring a front-end component, and assigns them to specialized sub-agents simultaneously. This parallel processing reduces the time you spend waiting for the AI to finish sequential tasks.

After these sub-agents complete their work, the supervisor uses a 'join' node to synthesize the results. It reviews the code from the sub-agents, runs tests to ensure they work together, and merges them into the main codebase. This structure prevents the 'context drift' that happens when one agent tries to do too many things at once. By narrowing the focus of each sub-agent to a single node in the graph, you maintain high fidelity in the output. You are no longer managing a chat history; you are managing an automated assembly line.

Using Routers and Model Context Protocol

To make this system robust, the supervisor acts as a 'router.' If a sub-agent encounters an error or lacks the necessary data, the supervisor detects this failure and redirects the task. For example, if a sub-agent cannot find a specific library, the router might trigger a search tool or ask you for the correct version. This logic ensures the loop doesn't break when it hits a minor obstacle. As you connect your environment to external data through the Model Context Protocol (MCP), your supervisor agent gains a standardized way to pull in documentation or database schemas, feeding that specific context only to the sub-agents that need it.

This delegation model relies on human-in-the-loop checkpoints. A well-designed Manager Loop includes explicit pauses where the supervisor presents its plan or its progress for your review. You aren't just watching the agent work; you are providing the high-level risk assessment that the AI lacks. By focusing on these outcomes rather than the individual lines of code, you can oversee much larger technical migrations or feature builds than you could by chatting with a single model. The goal is to move from manual guidance to automated oversight, where your primary task is confirming the logic of the graph.

Key takeaways

  • Establish a supervisor agent to interview you and create a 'recipe card' before any technical work begins.
  • Use the 'fan-out' pattern to delegate independent sub-tasks to multiple sub-agents for parallel execution.
  • Implement 'join' nodes where the supervisor reviews and integrates sub-agent outputs to prevent code conflicts.
  • Apply the 'router' pattern to handle errors by redirecting failed tasks back to the supervisor or the user.
  • Utilize the Model Context Protocol (MCP) to provide sub-agents with specific, relevant data without cluttering the main project context.
